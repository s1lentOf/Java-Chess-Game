GameService Architecture

Chess Project - Board & GameService Communication Design Document

SD2 Project Group 15 | April 2026

1. Architecture Overview

The architecture follows a delegation pattern where Board handles only UI rendering and input detection, while GameService owns all game logic, state, and board mutations. Communication is synchronous via method calls that return a MoveResult value object.

Game.Game (entry point) | |--- creates ---> Board (UI layer) |--- creates ---> GameService (logic layer) | | Board --------uses--------> GameService | | | | | handleSquareClick() | handleAction() -> MoveResult | | refreshBoard() | getLegalMoves() | | drawPiece() | isCorrectTurn() | | | | | Piece.getPossibleMoves() | | (raw moves, unfiltered) | MoveResult (immutable return value - no shared mutable state)

Key principle: Board never mutates piecesOnTheBoard[][] for game moves. Every move goes through GameService.handleAction(), which internally updates the board array, game state, and returns a MoveResult describing what happened.

4. Communication Flows

4.1 Normal Move

1
User clicks a square. Board.detectMouseClickPosition() translates pixels to IndexPosition.
2
Board.handleSquareClick() calls gameService.handleAction(clicked, piecesOnTheBoard).
3
GameService internally:
a) Checks if it's a selection, reselection, or move attempt.
b) Calls getLegalMoves(selected, board) which internally calls piece.getPossibleMoves(board) then filters via filterMovesForCheck().
c) If valid, calls executeMove() to mutate the board array.
d) Calls switchTurn(), updateCastlingRights(), updateMoveHistory().
e) Checks isInCheck(), isCheckmate(), isDraw() for the opponent.
f) Builds and returns MoveResult.
4
Board reads the returned MoveResult:
- Calls refreshBoard() to redraw pieces.
- If result.isCheckmate → shows game over dialog.
- If result.isDraw → shows draw dialog.
- If result.isCastle → rook already moved in array, refresh handles it.
- If result.isPromotion → shows promotion picker dialog.

4.2 Castling Move

1
User selects King, clicks target 2 squares away (e.g. King at e1 clicks g1).
2
Board calls gameService.handleAction(g1, board).
3
GameService.getLegalMoves(king, board) already includes g1 as a legal move (because canCastleKingside() returned true). executeMove() detects it's a castle and calls executeCastle() which moves both King (e1→g1) and Rook (h1→f1) in the board array.
4
Returns MoveResult with isCastle=true, rookFrom=(0,7), rookTo=(0,5). Board calls refreshBoard() and both pieces appear in new positions.

4.3 En Passant

1
Opponent's pawn moved 2 squares forward on previous turn. GameService stored this in lastMoveFrom, lastMoveTo, lastMovedPiece.
2
User selects own pawn adjacent to opponent's pawn. getLegalMoves() checks getEnPassantTarget() and adds the en passant capture square to legal moves.
3
User clicks the en passant square. executeMove() detects en passant, calls executeEnPassant(): moves capturing pawn diagonally, removes captured pawn from its actual square.
4
Returns MoveResult with isEnPassant=true, capturedPawnPos=(row, col).

4.4 Check Leading to Checkmate

1
White moves a piece. GameService.executeMove() completes the move.
2
isInCheck(BLACK, board) returns true.
3
hasNoLegalMoves(BLACK, board) iterates ALL black pieces, calls getLegalMoves() for each. Every move is filtered by filterMovesForCheck() — no move can get Black out of check.
4
Returns MoveResult with isCheck=true, isCheckmate=true. Board shows game over.

7. Board.handleSquareClick() - Before & After

Before (current - all logic in Board)

public void handleSquareClick(IndexPosition nextMove) {
    Piece targetPiece = piecesOnTheBoard[nextMove.getRow()][nextMove.getCol()];

    if (selected == null) {
        if (targetPiece != null) {
            selected = targetPiece;
        }
        return;
    }

    if (targetPiece != null) {
        if (!selected.isEnemy(targetPiece)) {
            selected = targetPiece;
        } else if (isMovePossible(selected.getPossibleMoves(piecesOnTheBoard), nextMove)) {
            capturePiece(nextMove);
        }
    } else if (isMovePossible(selected.getPossibleMoves(piecesOnTheBoard), nextMove)) {
        moveSelectedPiece(nextMove);
    }
}

After (delegates to GameService)

public void handleSquareClick(IndexPosition nextMove) {
    MoveResult result = gameService.handleAction(nextMove, piecesOnTheBoard);

    refreshBoard();

    if (result.isCheckmate()) {
        // Show game over dialog
        JOptionPane.showMessageDialog(null,
            gameService.getCurrentTurn() + " is checkmated! Game.Game over.");
    } else if (result.isDraw()) {
        JOptionPane.showMessageDialog(null,
            "Game.Game is a draw: " + result.getDrawReason());
    } else if (result.isPromotion()) {

    }
}

8. How Pins Work (No Explicit Pin Logic Needed)

A common misconception is that pins need dedicated detection code. With the filterMovesForCheck() approach, pins are handled automatically:

getLegalMoves(piece, board):
    rawMoves = piece.getPossibleMoves(board)      // piece doesn't know about pins
    legalMoves = []

    for each move in rawMoves:
        simulatedBoard = simulateMove(piece, move, board)  // copy board, apply move
        if NOT isInCheck(piece.color, simulatedBoard):     // does this expose my king?
            legalMoves.add(move)                           // no -> legal move
                                                           // yes -> filtered out (pinned!)
    return legalMoves

If a bishop is pinned to its king by an enemy rook, any bishop move that isn't along the pin line will leave the king exposed. simulateMove + isInCheck catches this automatically. No separate "isPinned" flag or pin detection is required.

Note: The simulateMove() approach is simple and correct. For each candidate move, it creates a shallow copy of the 8x8 array, applies the move, and checks if the king is attacked. With at most ~27 possible moves per piece and 32 pieces to scan for attacks, this is fast enough for a chess game (no performance concern).
